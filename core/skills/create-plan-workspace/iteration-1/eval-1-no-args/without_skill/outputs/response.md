# Response: "Help me create an implementation plan"

Sure! To create a solid implementation plan, I'll need a bit more context. Here are some questions to get us started:

1. **What are you building?** - Describe the feature, fix, or change you want to implement.
2. **What's the scope?** - Is this a small change, a new feature, or a larger refactor?
3. **What's the current state?** - Is there existing code we're modifying, or is this greenfield?
4. **What are the success criteria?** - How will you know the implementation is done and correct?
5. **Any constraints?** - Technology choices, deadlines, dependencies, or things to avoid?

---

Once I have that context, I can help you create a plan that covers:

### Typical Implementation Plan Structure

**1. Goal & Context**
- What problem are we solving?
- Why now, why this approach?

**2. Research / Pre-work**
- What do we need to understand before writing code?
- Relevant files, APIs, existing patterns to follow

**3. Implementation Steps**
- Ordered, concrete tasks (ideally small and independently verifiable)
- Each step should be testable before moving to the next

**4. Testing Strategy**
- What tests will validate the work?
- Edge cases and failure modes to cover

**5. Success Criteria**
- Checklist of observable outcomes that confirm the plan is complete

**6. Risks & Rollback**
- What could go wrong?
- How do we recover if something breaks?

Go ahead and share what you're working on and I'll help you draft the full plan.
